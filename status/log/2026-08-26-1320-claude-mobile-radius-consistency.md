# Mobile: border radius consistency pass

- User asked that on each page, the border radius of elements should be the same.
- Audited every screen's `borderRadius` usage (`grep -rn "borderRadius:"` across `app/` and `components/`) and compared values per page.
- Finding: the app already follows a consistent, deliberate two-tier system almost everywhere — `radius.lg`/`radius.xl` (both 18, aliased to the same value) for primary cards (Account's profile/preference cards, project detail's overview/notes/invoices cards, invoice summary cards, checkout's payment card), `radius.md` (14) for nested rows/fields/buttons (InvoiceRow, NotificationRow, TextField, Button, notes input). Circles (avatars, phase-tracker dots), pills (status badges, buttons), and NoteBubble's intentional asymmetric "tail" corner (16 main / 4 pulled corner, a standard chat-bubble affordance) are correctly exempt — forcing those to match a card's radius would look wrong, not more consistent.
- One real mismatch found: `app/(app)/projects/[id]/notes.tsx`'s composer `sendButton` (46×46) used `radius.lg` (18) while the `input` field directly beside it in the same row (also 46 tall) used `radius.md` (14) — visibly different rounding on two adjacent, same-height elements. Fixed to `radius.md` to match.
- Also normalized a literal `borderRadius: 999` to the `radius.pill` token on `app/(app)/projects/[id]/index.tsx`'s status pill — same rendered value, just consistent with how every other pill in the app is written.
- Considered and explicitly left alone: `checkout.tsx`'s `fieldMock`/`fieldMockText` styles use `radius.sm` (12), differing from `TextField`'s `radius.md` (14) — but that style is dead code, never referenced in the file's JSX, so it's invisible and not a real page-level inconsistency. Didn't remove it since cleanup wasn't the ask.
- Verified with `npx tsc --noEmit` from `mobile/`. Not run on a device/simulator this session.
- Committed `mobile/app/(app)/projects/[id]/notes.tsx` and `mobile/app/(app)/projects/[id]/index.tsx` together; both also carried unrelated pending translation-string work already uncommitted in those files, consistent with the user's earlier go-ahead to bundle that in.
