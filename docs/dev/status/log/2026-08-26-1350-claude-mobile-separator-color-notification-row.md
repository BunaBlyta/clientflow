# Mobile: notes separator color fix, notification row redesign

- Follow-up to the earlier notes header separator visibility fix: user reported the `color.borderStrong` token used for it looked green (correct — every border/neutral token in this app's palette carries a deliberate sage tint by design, per `lib/theme.ts`). Replaced with a one-off plain neutral gray (`#D8D8D8` light / `#454545` dark, computed via `mode` from `useTheme()`), not a design-system token, since no existing token is actually neutral. Lightened once more after the first pass looked too dark.
- User asked to remove the left rail from notification rows. Removed the `rail` `View` and its style from `components/NotificationRow.tsx` (used by both `app/(app)/home.tsx`'s activity list and `app/(app)/notifications/index.tsx`), and changed the row's `paddingRight: spacing.md` / `paddingLeft: spacing.sm` split (asymmetric to make room for the rail) to a symmetric `paddingHorizontal: spacing.md`.
- User then asked for the notification icon/background color for "grey" notification types to change. `typeColor()` previously gave neutral types (`PROJECT_STAGE_CHANGED`, `INVOICE_ISSUED`, `REQUEST_SUBMITTED`, `EXTRA_CHARGE_CREATED`) `color.textSecondary` (grey) while `NEW_NOTE` got `color.accent` — collapsed that split so everything defaults to `color.accent` except the two semantic cases (`PAYMENT_SUCCEEDED`/`REQUEST_APPROVED` → success, `PAYMENT_FAILED`/`REQUEST_REJECTED` → danger). Also changed the matching icon background fallback from `color.surface`/`color.surfaceMuted` to `color.accentSoft` so the icon chip's background matches its now-accent-colored icon, the same pairing pattern already used for the success/danger cases.
- Verified with `npx tsc --noEmit` from `mobile/`. Not run on a device/simulator this session — iterated on the separator color based on the user's live visual feedback rather than a screenshot.
- Three commits: notes.tsx (separator lighten), NotificationRow.tsx (rail removal + recolor).
